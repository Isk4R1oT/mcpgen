<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User-supplied spec content | URL or inline text supplied by CLI / engine API caller — UNTRUSTED |
| Outbound spec URL fetch | httpx GET to user-supplied origin — could be SSRF target |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-2-05 | DenialOfService | prance circular-ref recursion blowup (Pitfall C, verified on Stripe 2026-04-26) | mitigate | `recursion_limit=2 + recursion_limit_handler=lambda l, r, recs: {"type": "object"}` replaces deeply-nested cycles with a placeholder; verified via `tests/fixtures/circular_ref_spec.json` |
| T-2-06 | DenialOfService | Huge spec (raw or post-resolve) consuming all memory | mitigate | Pre-fetch `Content-Length` check; raw size check after read; resolved size check via `len(json.dumps(resolved))`; reject with `SPEC_TOO_LARGE` |
| T-2-07 | InformationDisclosure | SSRF via user-supplied URL or remote $ref | accept-Phase-2 | D-13 — strict timeouts (30s) + body limit (10MB) + ≤3 redirects per fetch acceptable on localhost; allowlist DEFERRED to Phase 6 (acceptable risk per D-53; user supplies URL deliberately on localhost) |
| T-2-08 | Tampering | Malformed YAML/JSON triggering parser exploit | mitigate | `yaml.safe_load` (NOT `yaml.load`); `json.loads` defaults safe; both wrapped in try/except → `UNSUPPORTED_SPEC_FORMAT` |
| T-2-09 | InformationDisclosure | Spec content leaked to logs (Sentry/structlog) | mitigate | D-52 — never interpolate spec content into log messages; structlog calls only emit structural metrics (endpoint_count, spec_format, spec_hash); existing `_sentry_before_send` redacts auth headers (Phase 1 baseline) |
</threat_model>
