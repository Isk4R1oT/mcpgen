## Decisions Made

- **`parents[6]` for repo-root resolution from `template_loader.py`.** The plan's `parents[5]` lands at `apps/`, not the repo root. Verified by enumerating parents: `stage_e/[0] → stages/[1] → mcpgen_engine/[2] → src/[3] → generation-engine/[4] → apps/[5] → repo-root/[6]`. The corrected depth makes the FileSystemLoader resolve `packages/codegen-templates/templates/` correctly.
- **`StageEManifest.model_validate(dict)` instead of typed instances.** `datamodel-codegen` emits a synthetic `File` class for the inline `List[File]` reference inside `StageEManifest`, distinct from the named `StageEFileEntry` export. Pydantic strict-mode rejects `StageEFileEntry` instances when the field type is `List[File]`. Constructing via `model_validate({...})` from dicts avoids depending on the codegen artifact.
- **S701 (`autoescape=False`) noqa with rationale.** Stage E emits TypeScript / TOML / JSON / Markdown source code, not HTML — auto-escaping would double-escape backslashes and break codegen. The attribute-level `# noqa: S701` is paired with a 6-line module-level rationale.
- **`@cloudflare/workers-oauth-provider@^0.2.2` pin (resolved `0.2.4`).** The plan instructs `^0.2.2`. Latest stable per `npm view` (2026-04-28) is `0.4.0`. The `^0.2.2` form satisfies Plan 04-09's verify regex `~?0\.2\.[0-9]+`. Plan 04-09 wave 3 will revisit if a breaking-change-risk audit warrants moving to a stricter `~0.2.4`.
- **`ts_compile_passed` authoritative semantics codified in IR.** Per WARNING #5: `ts_compile_passed = true` ⇔ `tsc --noEmit` exit 0 with NO errors; warnings allowed and tracked separately in `ts_compile_warning_count`. Stripe/GitHub/Notion fixtures gate on `warning_count==0` per CONTEXT D-43.5; Linear/Slack assert `passed=true` only.

**1. [Rule 1 - Bug] Corrected `parents[5]` → `parents[6]` in template_loader.py path resolution**

- **Found during:** Task 2 (template_loader.py creation)
- **Issue:** The plan's `must_haves.truths` block specified `Path(__file__).resolve().parents[5]` to land at the repo root. From `apps/generation-engine/src/mcpgen_engine/stages/stage_e/template_loader.py`, `parents[5]` lands at `apps/`, not the repo root. Using the wrong depth would make `FileSystemLoader` look for templates in `apps/packages/codegen-templates/templates/` which doesn't exist; `Environment.get_template()` would raise `TemplateNotFound` immediately on Stage E entry.
- **Fix:** Verified parent depth empirically (Python enumeration); corrected to `parents[6]`. Documented the depth ladder in a code comment so future readers can audit.
- **Files modified:** `apps/generation-engine/src/mcpgen_engine/stages/stage_e/template_loader.py`

- **Committed in:** `b49258b` (Task 2 commit)

**2. [Rule 1 - Bug] Use `StageEManifest.model_validate(dict)` instead of typed `StageEFileEntry` instances**

- **Found during:** Task 2 (output_writer.py + first test run)
- **Issue:** `datamodel-code-generator` emits a synthetic `File` class for the inline `StageEManifest.files: List[File]` reference, separate from the named `StageEFileEntry` export. Initial code constructed `StageEManifest(files=[StageEFileEntry(...)])` which Pydantic strict-mode rejected with `Input should be a valid dictionary or instance of File`.
- **Fix:** Switched to `StageEManifest.model_validate({"files": [{...dict...}], ...})` — Pydantic coerces dicts into the inline `File` class without dependency on the codegen artifact. `StageEFileEntry` remains the public API consumers use (Plans 04-11/04-12 read manifests via `StageEManifest.files` whose runtime type is the codegen `File` class — fields are identical).
- **Files modified:** `apps/generation-engine/src/mcpgen_engine/stages/stage_e/output_writer.py`
- **Verification:** `test_write_files_atomically_emits_manifest` round-trips manifest construction + sha256 verification per file.
- **Committed in:** `b49258b` (Task 2 commit)

**3. [Rule 3 - Blocking] Suppressed S701 (`autoescape=False` is XSS risk) with attribute-level noqa + rationale**

- **Found during:** Task 2 (ruff check on `template_loader.py`)
- **Issue:** Ruff's bandit ruleset flags `Environment(autoescape=False)` as a hard error. Stage E intentionally disables auto-escape because it emits TypeScript / TOML / JSON / Markdown source code (auto-escape would double-escape backslashes and break codegen). The plan explicitly lists `autoescape=False` as a required configuration value.
- **Fix:** Added `# noqa: S701 — see docstring; Stage E emits source code, not HTML` on the `autoescape=False` line + 6-line module-docstring rationale referencing the explicit `| tojson` filter that user-controlled spec data flows through (so input sanitization remains explicit).
- **Files modified:** `apps/generation-engine/src/mcpgen_engine/stages/stage_e/template_loader.py`
- **Verification:** `ruff check` exits clean.
- **Committed in:** `b49258b` (Task 2 commit)

**4. [Rule 3 - Blocking] Removed unused `# type: ignore[assignment]` comment in test_scaffold.py**

- **Found during:** Task 2 (mypy on tests/stages/stage_e/)
- **Issue:** mypy reported `Unused "type: ignore" comment` because `dict.update`-style narrow assignments don't require a type ignore in current mypy. The comment was vestigial from an earlier draft.
