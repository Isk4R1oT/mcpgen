## Decisions Made

- **app.jsx not in commit (1-of-12 difference from plan frontmatter `files_modified`):** `git status --porcelain apps/web/src/*.jsx` shows 11 modified JSX files (not 12). app.jsx is already SSR-safe — no top-level `window.X` references. The plan frontmatter pre-emptively listed all 12 files; Task 1's audit confirmed only 11 needed guards. Final staged set matches actual scope.
- **Hook upgrade pattern: mirror CI guard, not invent new escape hatch.** The upgrade copies `PAIRED_ADR_PATTERN` regex byte-for-byte from `.github/workflows/scripts/visual-lock-guard.sh:19` and uses the same 3-branch logic. This guarantees that any commit accepted by the local hook will also be accepted by CI — no surprise PR-time failures.
- **Hook unit test in temp git repos via mktemp + git init.** Avoids polluting the live repo's `git diff --cached` state. Each scenario gets a fresh repo, init commit, file staging, hook run, exit-code assertion. The 3 cases collectively prove: (a) hook is no-op on non-locked changes, (b) hook accepts the paired-ADR escape hatch, (c) hook still rejects bare locked-file edits (T-9.1-01-05 mitigation: regex not weakened).
