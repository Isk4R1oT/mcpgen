## One-liner

Replaced the plan-02 stubs for `/api/v1/generate` + `/api/v1/jobs/:id[/stream]` + `/api/v1/deploy/ephemeral` + `/api/v1/claim_generation` with cookie-aware Hono handlers that mint and validate the `mcpgen_anon_session` ULID HttpOnly cookie, plus added a GET `/` cold-start landing handler that rotates the cookie defensively per the T-9.1-claim session-fixation threat — all four endpoints now form the public surface plans 04 / 05 / 06 / 08 / 09 compose against.

## What was built

### Task 1 — TDD RED (commit `f3ce1a0`)

Two vitest suites pin the cookie shape + session-fixation behavior BEFORE any implementation lands:

- **`apps/api/tests/anon-session-cookie.test.ts`** (6 cases):
  1. Anon `POST /api/v1/generate` without cookie → Set-Cookie carries 26-char ULID + `HttpOnly` + `SameSite=Lax` + `Path=/` + `Max-Age=604800`.
  2. `ENVIRONMENT='production'` → `Secure` flag present.
  3. `ENVIRONMENT='development'` → `Secure` flag absent.
  4. Existing valid ULID cookie → no Set-Cookie re-issue (idempotent).
  5. Malformed cookie value (not ULID format) → re-issued with fresh ULID.
  6. Oversized cookie value (pollution attempt) → re-issued.
- **`apps/api/tests/anon-session-fixation.test.ts`** (4 cases, threat ID `T-9.1-claim` referenced in file header for grep):
  1. `GET /` with no Referer → cookie rotated.
  2. `GET /` with same-origin Referer → cookie persists.
  3. `GET /` with off-origin Referer (`https://evil.com`) → cookie rotated.
  4. `POST /api/v1/generate` with valid cookie + off-origin Referer → cookie persists (POST is not a "cold-start landing").

All 10 tests fail RED (7 explicit failures + 3 conditional assertions falling through `if (cookie !== null)` guards) — exactly what we wanted before writing the implementation.

## T-9.1-claim regression test result

The fixation defense is exercised by `tests/anon-session-fixation.test.ts`:

- ✅ Test 1 — `GET /` with no Referer + planted attacker cookie `01HXAAAAAAAAAAAAAAAAAAAAA1` → server responds with a fresh, distinct ULID in Set-Cookie.
- ✅ Test 2 — `GET /` with same-origin Referer (`http://api.mcpgen.test/some/internal/page`) + planted cookie → no rotation (server returns no Set-Cookie OR returns the same value).
- ✅ Test 3 — `GET /` with off-origin Referer (`https://evil.com/landing`) + planted cookie → fresh ULID issued.
- ✅ Test 4 — `POST /api/v1/generate` with valid cookie + off-origin Referer → cookie persists (fixation logic deliberately does NOT fire on POST; this is the bypass-prevention guard for the GET-only fixation surface).

The mitigation works because `isColdStartLanding(c)` only inspects Referer, and the only route that calls `ensureAnonSession({ forceReissue: isColdStartLanding(c) })` with the cold-start flag is `GET /` — every other surface (POST `/generate`, GET `/jobs/:id`, etc.) uses `forceReissue: false` so a valid in-flight session is never gratuitously rotated.

## Cookie shape — locked

```
Set-Cookie: mcpgen_anon_session=01HXFL1ABCDEFGHIJKLMNOPQRS;
            HttpOnly; SameSite=Lax; Path=/; Max-Age=604800
            (+ Secure when ENVIRONMENT='production')
```

Value: 26-char Crockford-base32 ULID (regex `/^[0-9A-HJKMNP-TV-Z]{26}$/`).
Max-Age: 7 days = 604800 seconds (matches D-04 + D-06 retention).
