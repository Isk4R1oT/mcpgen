# Phase 9.1 Plan 06: L1 Cache-Hit Path + SSE Replay Summary

## One-liner

Brilliant founder insight (CONTEXT D-05) shipped: incoming anon spec hashes hit
the L1 cache (verified+, ≤7d, no chains) and replay a synthetic 9-stage SSE
timeline in <1s instead of running the engine pipeline; OQ-2 resolved via
`generations.cached_from_generation_id` FK on every cache-hit child row, so
each anon user has their own claimable record and analytics distinguishes
cache-served from fresh.

```typescript
let jobId = `gen_${ulid()}`;

    const specHash = await computeSpecHash(parsed.data);
    const cached = await lookupCachedGeneration(specHash);

  }
}
if (anonSessionId !== null && !cacheHit) {

  await persistAnonGeneration({ generationId: jobId, anonSessionId, ipHash });
}
```

#### `apps/api/src/routes/v1/jobs/anon-stream.ts` — cache-replay branch

`loadCachedSource(jobId)` JOINs `generations` to itself:

```sql
SELECT
  g.cached_from_generation_id, cg.id, cg.quality_score, cg.created_at,
  cg.ir, cg.quality_report
FROM generations g
LEFT JOIN generations cg ON cg.id = g.cached_from_generation_id
WHERE g.id = $1
LIMIT 1
```

Returns null when `cached_from_generation_id` is null (fresh path) or when
the source row was deleted (FK ON DELETE SET NULL — defensive null
handling).

The `/:id/stream` handler then:
1. Authorizes via `resolveAuthSignals(c)` (existing plan 03 logic)
2. If authorized: tries `loadCachedSource(jobId)`; on hit builds the
   replay timeline and streams via `streamCacheReplayTimeline` honoring
   `Last-Event-ID`
3. On miss / DB error: falls through to the existing Phase-09.1-03 stub
   (which itself defers to Phase 8 `stream.ts` for fresh-job streams)

## Cache-hit decision matrix

| Criterion | Required | Source |
|---|---|---|
| `specs.content_hash = $spec_hash` | yes | D-05 / RESEARCH §10 — Stage A canonical hash |
| `g.quality_score >= 4.0` | yes | D-05 — verified+ floor |
| `g.is_publishable = true` | yes | Phase 9 plan 02 — explicit publish flag |
| `g.created_at >= NOW() - INTERVAL '7 days'` | yes | D-05 — freshness |
| `g.cached_from_generation_id IS NULL` | yes | Pitfall #6 — never chain |
| `ORDER BY quality_score DESC, created_at DESC LIMIT 1` | yes | tiebreak — highest quality first, then most recent |

## Spec-hash flow (current vs target)

| Step | Current (plan 09.1-06) | Target (post engine `/internal/v1/parse`) |
|------|--------------------------|--------------------------------------------|
| 1. Compute hash | BFF: `sha256(spec_url || spec_content)` raw | Engine: `sha256(_canonicalize(parsed_spec_dict))` |
| 2. Cache lookup | `WHERE specs.content_hash = $hash` | `WHERE specs.content_hash = $hash` |
| 3. HIT semantics | Identical request body → identical hash | Semantically-equal specs (whitespace / key-order / YAML vs JSON variants) → identical hash |
| 4. Swap-in | `await fetch(${ENGINE_ENDPOINT}/internal/v1/parse).content_hash` replaces `computeSpecHash` body | One-line change inside generate.ts |

The fallback path covers the majority anon-flow case (a user pasting the same
URL twice), which is exactly what D-05 brilliant-insight is optimizing for.
Whitespace-tolerant cache hits arrive when the engine endpoint lands.

## OQ-2 attribution model summary

OQ-2 (CONTEXT D-09): "How do we attribute a cache-served generation to the anon
who consumed it without polluting the original premium gen's stats?"

Resolution shipped here:

1. **Original gen** — owned by some authed org; `cached_from_generation_id IS
   NULL`; `is_publishable = true` after F2/F3 quality gates pass.
2. **Cache-hit child gen** — owned by NO org (anon); `cached_from_generation_id
   = original.id`; `llm_cost_usd = 0` (cache hits are free); `is_publishable
   = false` (children never propagate as future cache sources).
3. **Anon claim flow (plan 09.1-09)** — when the anon converts, the existing
   `anonymous_generations.claimed_by_org_id` mechanism flips OWNERSHIP of the
   CHILD row to the new org. The original is untouched. Per-anon claim
   semantics preserved.
4. **Analytics** — `WHERE cached_from_generation_id IS NULL` counts FRESH
   generations; `WHERE cached_from_generation_id IS NOT NULL` counts
   CACHE-SERVED. Cost reports filter on `llm_cost_usd > 0` to exclude cache
   hits naturally.

## Threat Flags

No new threat surface beyond the threat model declared in the plan
(T-9.1-06-01 through T-9.1-06-05). Specifically:

- **T-9.1-06-01** (cache-hit metadata leak): mitigated — replay only includes

- **T-9.1-06-02** (cache poisoning via false 4.0+ score): mitigated by F2 +

- **T-9.1-06-05** (drift watcher seeing cached row as fresh): mitigated —
  drift watcher operates on `specs.content_hash`, not
