# Phase 9.1 — Anonymous Hero Flow + Claim Generation

## Phase Summary

Restore the originally-specced anonymous hero flow that Phase 8 silently broke. Anonymous users complete the **landing → paste URL → SSE generation → preview code → quality report** sequence WITHOUT signup. Auth gate moves from BFF blanket `/api/v1/*` to per-route policy, with **playground**, **ZIP download**, and **permanent deploy** behind signup. **MCPGen Cloud 24-hour ephemeral trial** is anonymous-friendly to maximize "wow → signup" conversion. The first authenticated generation is "claimed" from the anonymous session via HttpOnly cookie.

**Goal (one sentence):** Anonymous user pastes Stripe OpenAPI URL → 60s later sees real preview + quality badge in browser, with one click to deploy a 24h-ephemeral MCPGen Cloud URL — all without signup; signup happens only when they want to keep it / use the live playground / download the source.

**Unit of correctness:** Local-stack test from 2026-04-30 (HTTP 401 on `POST /api/v1/generate` from landing-page submit) returns **HTTP 202** instead.

## Decisions (D-01 … D-12)

### D-01 — Auth gate position: **playground-step (and ZIP download + permanent deploy)** (locked)

**Decision:** The auth boundary sits between **quality-report screen (anon)** and **playground / ZIP download / permanent deploy (auth-required)**.

| Step | Auth required? |
|------|---------------|
| Landing (`/`) | ❌ public |
| Live preview (parse during paste) | ❌ public |
| `POST /api/v1/generate` | ❌ public (rate-limited per D-02) |
| SSE progress stream `/api/v1/jobs/:id/stream` | ❌ public (within same anon session) |
| Preview code screen (`/generate/:id/preview`) | ❌ public |
| Quality report screen (`/generate/:id/quality`, F2/F3 badges visible) | ❌ public |
| **Playground (`/generate/:id/playground`)** — runs real LLM agent against the MCP | ✅ **gate here** |
| **Deploy to MCPGen Cloud (24h ephemeral trial)** | ❌ public — see D-03 |
| **Deploy to MCPGen Cloud (permanent)** | ✅ |
| **Download ZIP / Docker self-host bundle** | ✅ |
| `/dashboard/*` | ✅ |

**Rationale:** Founder ergonomics — playground requires real LLM API calls (more expensive than the generation itself: ~10-50 tool calls × LLM tokens). Gating at deploy-only would force a separate playground rate-limiter, which is anti-pattern (two layers of throttling on the same anon-cookie context). Gating at playground is a single boundary that protects both expensive playground LLM calls AND the "I want to keep this" deploy commitment, while preserving the full "wow moment" through quality report.

**Flex requirement (founder-stated):** the gate position must be a **config switch**, not hardcoded. `BFF_ANONYMOUS_GATE = "playground" | "preview" | "quality" | "deploy"` env var, default `"playground"`. Plan must verify changing the env var moves the gate without code change. Closes founder concern: "надо сделать гибко чтобы мы если что могли поменять модель работы при необходимости".

### D-02 — Anonymous abuse prevention: **1 generation per IP per 24h + cost cap $0.50** (locked)

**Decision:** TimescaleDB-backed IP rate limiter:
- Hash IP → `sha256(ip + daily_salt)` to avoid storing raw PII (salt rotates daily UTC)
- Insert into `anon_generation_log (ip_hash, generation_id, created_at)` on every anon `POST /generate`
- Before accepting new anon gen, count rows where `ip_hash = $1 AND created_at >= NOW() - INTERVAL '24h'`
- If `count >= 1` → return **429 Too Many Requests** with `{"error": "anon_rate_limit", "message": "Anonymous tier limited to 1 generation per 24 hours. Sign up for 5/month free.", "signup_url": "/sign-up"}`
- Cost cap $0.50 per anon generation enforced via existing engine cost-tracker (no new code; reuses Phase 4/5 cost-cap)

**Bypass during testing:** localhost requests (`x-forwarded-for == 127.0.0.1` OR no proxy header in dev mode) are exempt — founder/CI never blocked.

**Rationale:** 1/IP/24h covers 99% of legit "evaluate the product" use cases (most users try once and decide). Higher abuse cost ($0.10 OpenRouter cost × N IPs) bounded by daily salt rotation (attacker can't scrape millions of IPs in advance). $0.50 cost cap is the existing free-tier ceiling; anon inherits it.

**Cloudflare Turnstile:** explicitly NOT in v1. Re-evaluate if abuse logs show >50 anon gens/day from non-residential IPs in launch week.

### D-03 — Anonymous deploy targets: **MCPGen Cloud 24h ephemeral trial** (locked)

**Decision:** What anonymous user can do with a successfully-generated MCP server:

| Target | Anon access? | Behavior |
|--------|--------------|----------|
| **MCPGen Cloud (ephemeral)** | ✅ | One-click deploy → returns `https://anon-{nanoid}.mcpgen.app/mcp`. CF Workers for Platforms tenant tagged `anon=true`, `expires_at=NOW() + 24h`. Dispatch worker rejects with 410 Gone after expiry. Auto-cleanup cron deletes expired anon tenants. Founder concern: "MCPGen Cloud да 24 часа пробный период". |
| **MCPGen Cloud (permanent)** | ❌ signup required | Standard tenant flow per Phase 6. Anon trial URL gets "claimed" and re-tagged as permanent on signup (via D-04 cookie). |
| **Self-host ZIP / Docker bundle** | ❌ signup required | Founder explicitly blocked: "Давать бесплатно скачивать это ту мач". Without signup, screen shows preview code IN BROWSER (read-only) but no download button. |
| **CLI `mcpgen init` (open-source)** | ✅ | The CLI from `apps/cli` is open-source; runs locally and bypasses our hosted infra. The CLI gate is OUT OF SCOPE for this phase (cli does its own auth via OPENROUTER_API_KEY). |

**Anon-tenant resource limits:** 100 tool-calls / 24h on the ephemeral URL. Hard cap at 24h regardless of usage. Bandwidth-billed against MCPGen account (we eat the cost as customer-acquisition).

**Rationale:** 24h ephemeral cloud deploy is the maximum-conversion pattern: user gets a real URL they can connect Claude Desktop to, sees the tools work end-to-end, then gets the "Sign up to keep this server" CTA when the expiry banner appears. Solves the "wow moment without commitment" problem precisely.

### D-04 — Claim mechanism: **HttpOnly cookie + `claim_generation` BFF endpoint** (locked)

**Decision:** Server-side anonymous session via HttpOnly cookie + Postgres-backed claim flow:

```
1. Anon user POSTs /api/v1/generate (no JWT)
2. BFF generates `anon_session_id = ulid()`, sets cookie:
     Set-Cookie: mcpgen_anon_session=<id>; HttpOnly; SameSite=Lax;
                 Secure (in prod); Path=/; Max-Age=604800 (7 days)
3. BFF creates row in `anonymous_generations (anon_session_id, generation_id,
     ip_hash, created_at, claimed_at NULL, claimed_by_org_id NULL)`
4. Subsequent anon requests within 7 days carry the cookie; BFF reads it
    to authorize access to the user's prior anon generations
    (prevents User A from seeing User B's anon gen by guessing IDs).
5. On signup completion, frontend calls POST /api/v1/claim_generation:
     - BFF reads `mcpgen_anon_session` cookie
     - Updates `anonymous_generations` rows: SET claimed_at=NOW(),
        claimed_by_org_id=$newOrgId WHERE anon_session_id=$cookie_id
     - Re-tags any anon-cloud-tenants from `anon=true, expires_at=...` to
        permanent (clears expires_at)
     - Clears the anon cookie (Set-Cookie: mcpgen_anon_session=; Max-Age=0)
6. Unclaimed anon generations expire from anonymous_generations after 7 days
    (cleanup cron) — generations table rows kept forever (cheap), but
    anon-cloud-tenants get hard-deleted at 24h expires_at.
```

**Rationale:** HttpOnly + SameSite=Lax matches the Phase 7 D-19 precedent (no localStorage). Postgres source-of-truth supports the Phase 7 D-11 "page-reload-mid-generation" test in the anon path. Cookie-based session + signed cookie attribute is industry standard (Vercel, Linear, Stripe all do this for anon→auth claim flows).

**Threat model (T-9.1-claim):** session-fixation attack (attacker sets cookie on victim's browser before victim logs in). Mitigated by re-issuing a fresh `mcpgen_anon_session` value on every cold-start landing visit (no fixation window after signup). Plan must include a vitest case proving this.

### D-05 — Cache reuse for anonymous (founder insight): **L1 spec-hash hit returns cached generation if quality ≥ verified** (locked)

**Decision:** Founder noted: "может как кеш его испльзвем когда другой пользователь вставит тот же url и будет вообще бесплатно и очень быстро". Implement:

```
1. On anon POST /generate, compute `spec_hash = sha256(spec_yaml_normalized)`
2. Look up in `generations` table:
     SELECT g.* FROM generations g
     WHERE g.spec_hash = $1
       AND g.quality_score >= 4.0          -- F2 ≥ 4.0 (verified or premium)
       AND g.is_publishable = true
       AND g.created_at >= NOW() - INTERVAL '7 days'  -- spec drift fresh
     ORDER BY g.quality_score DESC, g.created_at DESC
     LIMIT 1
3. If hit → return cached generation_id; SSE stream replays cached events
    in <1s (instead of running real engine pipeline 60s)
4. Anon user sees IDENTICAL preview/quality screens; signup flow still works
    (claim_generation links the cached row to their org without re-running engine)
5. anon_generation_log still gets a row (1/IP/24h still enforced)
6. Cache hit is REPORTED in SSE event-id=0 metadata: {"cache_hit": true,
    "original_quality": 4.6, "served_from": "2026-04-29T..."}
    so QualityReport screen shows "verified by 234 prior generations of this spec"
```

**Cache freshness:** 7 days. After that, drift watcher (Phase 8) may have invalidated the cache (upstream API changed). Re-run engine fresh.

**Quality floor:** only `verified` (F2 ≥ 4.0) or `premium` (F2 ≥ 4.5 + F3 ≥ 0.85) cached generations are reused for anon. `standard` and `needs_review` cached gens get re-run (we don't want anon users to see a bad first impression of a popular spec).

**Rationale:** Founder's cache idea is brilliant — converts the "anonymous tier = expensive" concern into a "anonymous tier = nearly free for popular specs". Stripe's OpenAPI spec is the canonical one most anon users will paste; after the first user generates it (or our W7 demo seeding), every subsequent anon for Stripe gets a cached premium-quality result for $0 LLM cost.

### D-06 — Anonymous gen retention: **7 days unclaimed → cleanup cron** (locked)

**Decision:**
- `anonymous_generations` rows expire after 7 days unclaimed (deleted by Inngest cron)
- `generations` rows are kept forever (no cleanup; cheap; useful for D-05 cache)
- `anon-cloud-tenants` (CF Workers for Platforms scripts tagged `anon=true`) are hard-deleted at `expires_at = created_at + 24h` — separate cron
- `anon_generation_log` (rate-limit table) rows expire at 30 days (Inngest cron) — keeps the IP-hash data lean while preserving 30 days for abuse forensics

**Rationale:** 7d = balance between "I generated this last week and want to claim it" (rare) and storage cost. 30 days for rate-limit log = matches Phase 9 outbox retention pattern.

### D-07 — Architecture flex: **per-route auth policy, NOT path-prefix middleware** (locked)

**Decision:** Replace the current blanket `/api/v1/*` Logto middleware with **per-route policies**:

```typescript
// apps/api/src/index.ts (refactor target)
const app = new Hono();

// PUBLIC routes (no auth)
app.route('/api/v1/generate',          generateRoute);    // anon-allowed (D-01..D-04)
app.route('/api/v1/jobs/:id/stream',   streamRoute);      // anon-allowed (cookie-scoped)
app.route('/api/v1/jobs/:id',          jobsStatusRoute);  // anon-allowed (cookie-scoped)

// PROTECTED routes (Logto JWT required)
const protectedApp = new Hono().use('*', authMiddleware);
protectedApp.route('/playground',      playgroundRoute);   // gate D-01
protectedApp.route('/download',        downloadRoute);     // gate D-03
protectedApp.route('/deploy',          deployRoute);       // permanent deploy gate
protectedApp.route('/dashboard/*',     dashboardRoutes);
protectedApp.route('/billing/*',       billingRoutes);
protectedApp.route('/claim_generation', claimRoute);      // D-04 — special: requires JWT but reads anon cookie

// HYBRID: anon OR Logto
app.route('/api/v1/deploy/ephemeral',   ephemeralDeployRoute);  // D-03 — anon-allowed but rate-limited
app.route('/api/v1/', protectedApp);
```

**Rationale:** the BFF_ANONYMOUS_GATE env var (D-01 flex requirement) is implemented as a config-driven route registration. Changing the env var moves which routes are in `app.route(...)` vs `protectedApp.route(...)`. Test: `BFF_ANONYMOUS_GATE=preview pnpm test` verifies playground becomes anon-allowed without code change.

### D-09 — DB schema additions (locked)

```sql
-- New: anonymous session tracking
CREATE TABLE anonymous_generations (
  anon_session_id   TEXT PRIMARY KEY,         -- ULID
  generation_id     UUID REFERENCES generations(id) ON DELETE CASCADE,
  ip_hash           TEXT NOT NULL,             -- sha256(ip + daily_salt)
  created_at        TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  claimed_at        TIMESTAMPTZ,
  claimed_by_org_id UUID REFERENCES organizations(id) ON DELETE SET NULL
);
CREATE INDEX anon_gen_session_idx ON anonymous_generations(anon_session_id);
CREATE INDEX anon_gen_ip_created_idx ON anonymous_generations(ip_hash, created_at DESC);

-- New: rate-limit log (kept separate so retention can be shorter)
CREATE TABLE anon_generation_log (
  id           BIGSERIAL PRIMARY KEY,
  ip_hash      TEXT NOT NULL,
  created_at   TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE INDEX anon_log_ip_time_idx ON anon_generation_log(ip_hash, created_at DESC);

-- Extend: deployments table for ephemeral anon tenants
ALTER TABLE deployments
  ADD COLUMN anon_session_id TEXT REFERENCES anonymous_generations(anon_session_id) ON DELETE SET NULL,
  ADD COLUMN expires_at      TIMESTAMPTZ;     -- NULL for permanent; NOW()+24h for anon
CREATE INDEX deploy_expires_idx ON deployments(expires_at) WHERE expires_at IS NOT NULL;
```

Drizzle migration named per Phase 8 convention: `infrastructure/neon/migrations/YYYYMMDDHHMMSS_phase09_1_anon_flow.sql`. Per Pitfall #18 use a fresh post-Phase-10 timestamp.

### D-11 — Security: IP capture from CF Workers + GDPR posture (locked)

**Decision:**
- IP source: `CF-Connecting-IP` header (set by Cloudflare for incoming requests; never trusted from client direct)
- Fallback for local dev: `x-forwarded-for` first hop OR `127.0.0.1` if neither present
- `ip_hash = sha256(daily_salt + raw_ip)` — daily salt rotates at UTC midnight via Inngest cron, stored in `app_secrets.daily_salt_current` row (single row, updated daily). Anon log retention 30d (D-06).
- After 30d, both raw_ip association AND old daily_salt are gone — rate-limit history is computationally unrecoverable
- Privacy policy update needed in Phase 10 plan 10-09 (legal pages): "We hash visitor IPs with a daily-rotating salt for 30 days to prevent abuse of our free tier; we never store raw IPs."

**Rationale:** GDPR-friendly (hashed PII with rotation = pseudonymized, not identified), founder-friendly (no IP-PII handling code paths to defend). Reuses existing Drizzle migration pattern.
