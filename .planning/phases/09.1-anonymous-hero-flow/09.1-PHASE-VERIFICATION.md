## 1. Bug Repro — Before / After

### Before (2026-04-30, on main, pre-Phase-9.1)

The original local-stack discovery (recorded in `09.1-CONTEXT.md` frontmatter `discovery` field):

> "Local-stack testing 2026-04-30: BFF /api/v1/generate returns 401 to anonymous landing-page submit. Phase 7 specced anonymous flow (07-CONTEXT D-18 + ux-flow.md §1.1 'Без регистрации'); Phase 8 implementation gated ALL /api/v1/* behind Logto JWT, breaking the design intent."

Equivalent shell repro (anonymous client without Authorization header against pre-Phase-9.1 BFF):

```text
$ curl -i -X POST http://localhost:8787/api/v1/generate \
    -H 'Content-Type: application/json' \
    -d '{"spec_url":"https://example.com/openapi.json"}'

HTTP/1.1 401 Unauthorized
Content-Type: application/json
{"error":"unauthorized","message":"Missing or invalid Authorization header"}
```

This 401 was caused by Phase 8 mounting `authMiddleware` at the `/api/v1/*` path-prefix, which violated `07-CONTEXT.md` D-18 ("anonymous users can paste a URL and run free-tier generation; auth gate at deploy step").

The four cases asserting `anon POST /api/v1/generate is non-401 under gate=...` are the byte-for-byte refutation of the original bug — the BFF now returns **HTTP 202** (cookie set + job queued) instead of HTTP 401 across all four `BFF_ANONYMOUS_GATE` settings.

The auth-boundary repositioning (plan 09.1-02) ungates `POST /api/v1/generate` for anonymous traffic; the cookie issuance (plan 09.1-03) creates the anonymous session; the rate-limit middleware (plan 09.1-05) inserts the IP-hash row.

**Why a unit test instead of a live curl:** the curl repro requires three running processes (web, api, engine). Plan 09.1-02 explicitly authored `auth-gate-position.test.ts` to exercise the exact same Hono app instance that Wrangler hosts in dev mode, with all four gate configurations — making the live curl redundant once vitest passes. The 26 cases collectively cover the gate matrix that a single curl never could.

### Playwright Wave-7 anon-spec gating — explicit honesty

The three Wave-7 specs (`anon-flow.spec.ts`, `anon-rate-limit.spec.ts`, `anon-claim-fixation.spec.ts`, totaling 7 tests) follow the Phase 9 OPS-02 nightly + pre-merge gate pattern:

```typescript
const RUN_E2E = process.env['RUN_E2E'] === '1';
test.skip(!RUN_E2E, 'requires RUN_E2E=1 (nightly + pre-merge gate)');
```

Without `RUN_E2E=1` they auto-skip (verified live: `7 skipped`). With `RUN_E2E=1` they require a running BFF on `localhost:8787` — when run without a dev server during this verification pass, all 7 fail with `ECONNREFUSED ::1:8787` from the first `apiRequestContext.post`, confirming **the test scaffolding is wired correctly and gated correctly**, but actual network execution requires the operator to start the local stack (or rely on CI/nightly).

This is the W7 operator carry-forward (item §6). Phase 9.1 itself ships the test specs, the BFF endpoints they exercise, and the unit/integration tests proving the logic — but the live three-process E2E run is operator-gated by design.
