# Phase 9.1 Plan 05: IP-hash daily-salt + 1/IP/24h Anon Rate Limiter Summary

## One-liner

Implemented the anonymous-tier abuse gate: `sha256(daily_salt + raw_ip)`-keyed
1/IP/24h rate limiter with **24h grace window via dual-hash lookup** (G-4
chosen over founder's hypothetical 30s; closes the salt-rotation race in
Pitfall #5), fail-open on DB outage, and IPv4/IPv6/RFC1918 localhost bypass
for founder/CI testing — wired into POST /api/v1/generate so
`anonymous_generations.ip_hash` now carries real hashed values instead of
the `'pending'` placeholder from plan 09.1-03.

### Task 2 — TDD GREEN (commit `cf58ed9`)

#### `apps/api/src/lib/anon-ip-hash.ts` — primitives

```typescript
export interface SaltPair { current: string; previous: string | null; }

// 60s in-memory TTL cache; reset by __resetSaltCache() post-rotation
export async function getCurrentSalts(): Promise<SaltPair>;

// Used on INSERT — ALWAYS uses current salt only
export async function hashIpForRateLimit(rawIp: string): Promise<string>;

// Used on SELECT — returns [current_hash, previous_hash] for 24h grace
export async function hashIpsForLookup(rawIp: string): Promise<string[]>;

export function extractRawIp(c: Context): string;
export function isLocalhostIp(ip: string): boolean;
export function __resetSaltCache(): void;  // test + cron post-rotate hook
```

Empty/missing `daily_salt_current` row triggers an explicit
`throw new Error(...)` — defense vs the silent-empty-salt-hash-collision
attack surface where every anon IP would map to the same hash and break
the rate-limit dimension entirely.

#### `apps/api/src/middleware/anon-rate-limit.ts` — Hono middleware

4-step flow with fail-open semantics on DB outages:

```
1. Auth bypass:    c.var.auth?.organizationId  → next()
                   OR  Authorization: Bearer ... → next()
2. Localhost bypass:  isLocalhostIp(rawIp) → next() (still tries to stash hash)
3. Real path:
   3a. hashIpsForLookup(rawIp) → [current_hash, previous_hash]
       (try/catch fail-open — no salts → next())
   3b. SELECT COUNT(*) FROM anon_generation_log
        WHERE ip_hash = ANY($1) AND created_at >= NOW() - INTERVAL '24 hours'
       (try/catch fail-open — query failure → next())
   3c. count >= 1 → 429 + canonical shape
4. Allow + persist:
   4a. hashIpForRateLimit(rawIp) → current-salt hash
   4b. INSERT INTO anon_generation_log (best-effort try/catch)
   4c. c.set('rateLimitedIpHash', hash)
   4d. next()
```

#### `apps/api/src/routes/v1/generate.ts` — wiring

```typescript
generateRoute.post('/', anonRateLimit, async (c) => {
  // ...
  const ipHash = c.var.rateLimitedIpHash ?? 'pending';
  await persistAnonGeneration({ generationId, anonSessionId, ipHash });
  // ...
});
```

`anonymous_generations.ip_hash` now carries the actual sha256 hash
(matches the `anon_generation_log.ip_hash` written by the middleware) —
plan 03's `'pending'` placeholder is gone.

## Hash-flow diagram

```
                 ┌─────────────────────────────────┐
 anon request ──→│ extractRawIp(c)                 │
                 │  CF-Connecting-IP > x-fwd > ::1 │
                 └────────────┬────────────────────┘
                              │
                ┌─────────────┴──────────────┐
                ↓                            ↓
        isLocalhostIp(ip)?           else: dual-hash lookup
        127.0.0.1, ::1,                       │
        192.168.*, 10.*                       ↓
                │                  hashIpsForLookup(ip)
                ↓                  ┌─[CURRENT salt]──→ hash_v_today
                                   └─[PREVIOUS salt]─→ hash_v_yesterday
                │                            │
                │                            ↓
                │                  SELECT COUNT(*) FROM anon_generation_log
                │                  WHERE ip_hash = ANY([hash_v_today, hash_v_yesterday])
                │                    AND created_at >= NOW() - INTERVAL '24 hours'
                │                            │
                │                  ┌─count >= 1 → 429 + signup_url
                │                  └─count == 0 → INSERT hash_v_today
                │                                  + c.set('rateLimitedIpHash', hash_v_today)
                ↓
        next()  (route handler reads c.var.rateLimitedIpHash and writes
                 anonymous_generations.ip_hash with it)
```

The Pitfall #5 mitigation is the diagonal: a request inflight at 23:59:59
that completes its INSERT against `current = salt_v1` is still found at
00:00:01 by `hashIpsForLookup` because the rotation cron promotes
`salt_v1 → daily_salt_previous` and the lookup includes both salts.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 — Bug] Authed callers reaching the public-mounted middleware were rate-limited**

- **Found during:** Task 2, rate-limit test 6 ("AUTH path skips middleware").
- **Issue:** The plan's interfaces block checks only `c.var.auth?.organizationId` — but the route is mounted on the PUBLIC side per Phase 09.1 plan 02 D-07 boundary, so `authMiddleware` does NOT run, and `c.var.auth` is always undefined for /api/v1/generate. A request carrying a valid JWT bearer was still hitting the anon gate.
- **Fix:** Added a presence-based bearer bypass — if `Authorization` header starts with `Bearer `, skip the gate. This matches D-02 product intent ("rate-limit applies ONLY to unauthenticated traffic"). A forged bearer to an anon route grants no privileged access (auth.ts validates everywhere it matters); they merely escape the anon quota — acceptable.
- **Files modified:** `apps/api/src/middleware/anon-rate-limit.ts` (lines 78-85).
- **Commit:** `cf58ed9`.

**2. [Rule 1 — Bug] Middleware threw 500s on every test that didn't mock db.execute**

- **Found during:** Task 2, full-suite run (5 regressions in `anon-session-cookie.test.ts` + 1 in `contract.test.ts`).
- **Issue:** The middleware ran `db.execute(...)` for the salts SELECT and the COUNT query without any error handling. Tests that don't mock `db.js` triggered Neon connection errors → uncaught throws → 500 responses → no Set-Cookie issued.
- **Fix:** Wrapped every DB-touching call site in `try/catch + console.warn` and **fail open** (`return next()`). The rate-limit gate is a behavioral throttle, not a security boundary; cost cap on the engine layer ($0.50/anon-gen) is the real spend floor. Failing closed on DB hiccups would deny the entire 60-second hero flow on every transient Neon outage — strictly worse UX than briefly permitting an extra anon gen.
- **Files modified:** `apps/api/src/middleware/anon-rate-limit.ts`.
- **Commit:** `cf58ed9`.

**3. [Rule 2 — Defense-in-depth] Empty `daily_salt_current` row would silently break rate-limiting**

- **Found during:** Implementation of `getCurrentSalts`.
- **Issue:** The plan's interfaces block defaults `current` to `''` when the row is missing. But hashing under empty salt produces `sha256(":${rawIp}")` — every anon IP collapses into a deterministic-by-IP output regardless of when, which silently breaks the rate-limit dimension (one global hash per IP across all time).
- **Fix:** Explicit `throw new Error('app_secrets.daily_salt_current row is missing; phase 09.1 migration not applied')` per CLAUDE.md "raise errors explicitly, never silently ignore them". The throw propagates up to the middleware's fail-open try/catch so production stays running, but the warning surfaces in logs immediately for operators.
- **Files modified:** `apps/api/src/lib/anon-ip-hash.ts` (lines 86-92).
- **Commit:** `cf58ed9`.

**4. [Rule 3 — Blocking] Drizzle `ANY(${arr})` test mock didn't recognize array-as-param**

- **Found during:** Task 2 first test run — rate-limit COUNT mock reported empty params, breaking tests 2 and 4.
- **Issue:** The reused `tests/routes/drift.test.ts` queryChunks introspection pattern only recognized StringChunks and `{ value: ... }` wrapped scalars. Drizzle's `ANY(${arr})` template inlines the array directly into the chunk stream as a plain JS `Array` instance (not wrapped) — neither branch caught it.
- **Fix:** Discriminator now uses `constructor.name === 'StringChunk'` for SQL fragments and treats plain `Array` instances as raw param values. Pattern is more robust than the prior heuristic-based approach.
- **Files modified:** `apps/api/tests/anon-rate-limit.test.ts` (mock factory).
- **Commit:** `cf58ed9`.
