## Hypertable chunk-interval verification

Test 5 of the vitest suite (active when `DATABASE_URL` is set) queries `timescaledb_information.dimensions` and asserts `chunk_time_interval` is exactly 1 day (either as `time_interval = '1 day'` text or `integer_interval = '86400000000'` microseconds). This is the canonical Pitfall #4 guard: a default 7-day chunk interval would silently coarsen the 30d retention pattern from 30 chunks (atomic 3.3% drop per call) to 4 chunks (atomic 25% drop per call) — the migration's behavior is now test-locked.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 — Blocking issue] Drizzle Kit auto-generated migration with wrong timestamp**

- **Found during:** Task 1, when running `drizzle-kit:generate` to obtain a correct snapshot for the new TS schema state.
- **Issue:** Drizzle Kit's `prefix: 'timestamp'` config emits the new migration file under `<current_clock>_<random_word>.sql` (`20260501105422_sticky_satana.sql`) and appends a journal entry idx=7 with that tag — colliding with the FROZEN target name `20260501010000_phase09_1_anon_flow.sql` (Pitfall #18 forbids any rename of a committed migration; the FROZEN name was assigned by the plan).
- **Fix:** Removed the auto-generated SQL file, removed the auto-appended journal entry idx=7, renamed the auto-generated `20260501105422_snapshot.json` to `20260501010000_snapshot.json` to match the FROZEN migration tag. The snapshot itself correctly captures the new TS schema state, so reusing it (rather than hand-rolling) preserves the chained `prevId` integrity.
- **Files modified:** `infrastructure/neon/migrations/meta/_journal.json` (idx=7 removed), filesystem renames in `infrastructure/neon/migrations/meta/`.
- **Commit:** `c60c587` (Task 1 — committed atomically with the SQL file).

**2. [Rule 3 — Blocking issue] Worktree had no `node_modules`**

- **Found during:** Task 2 typecheck attempt.
- **Issue:** Fresh git worktree starts without per-package node_modules; `pnpm --filter @mcpgen/contracts typecheck` fails with `tsc: command not found`.
- **Fix:** Ran `pnpm install --frozen-lockfile --prefer-offline` at the worktree root (10.5s with the warm pnpm store).
- **Files modified:** None (install only touches `node_modules/` which is gitignored).
- **Commit:** N/A (operational, not a code change).
