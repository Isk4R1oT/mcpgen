## What Shipped

### Cron #1 — `anon-tenant-cleanup-v1` (every 15 minutes)

Stable ID: `INNGEST_FUNCTION_IDS.ANON_TENANT_CLEANUP`. Schedule: `*/15 * * * *`.

```text
1. SELECT id, cf_worker_name FROM deployments
   WHERE expires_at IS NOT NULL
     AND expires_at < NOW()
     AND anon_session_id IS NOT NULL
   LIMIT 500
2. For each row:
   step.run(`delete-cf-${id}`):  deleteScript(cfEnv, cf_worker_name)
   step.run(`delete-db-${id}`):  DELETE FROM deployments WHERE id = ${id}
3. sendBetterStackHeartbeat(BETTERSTACK_ANON_CLEANUP_HEARTBEAT_URL)
4. return { deleted: N }
```

**Invariants:**

- LIMIT 500 caps each run to fit Inngest step time budget. Backlog
  clears at 4 runs/hour × 500 = 2K expired tenants/hour.
- 404 from CF DELETE = success (cf-platforms-deploy.ts wrapper invariant).
  Re-run after partial failure converges on "deleted".
- Filter requires BOTH `expires_at` and `anon_session_id` non-null —
  T-9.1-10-05: claim transaction (plan 09) sets both NULL atomically,
  so the cleanup query cannot race with a claim in flight.
- MCPGEN_LOCAL_COMPUTE delegated to cf-platforms-deploy.ts (single
  source of truth); the cron does NOT branch on it.
- BetterStack heartbeat fires on EVERY successful run including the
  0-deletes case (Pitfall #3 mandate — silent failure is dangerous).

### Cron #2 — `anon-rate-limit-cleanup-v1` (daily 04:00 UTC)

Stable ID: `INNGEST_FUNCTION_IDS.ANON_RATE_LIMIT_CLEANUP`. Schedule: `0 4 * * *`.

```text
step.run('drop-old-chunks'):
   SELECT drop_chunks('anon_generation_log', INTERVAL '30 days')
step.run('delete-old-unclaimed'):
   DELETE FROM anonymous_generations
   WHERE claimed_at IS NULL AND created_at < NOW() - INTERVAL '7 days'
   RETURNING anon_session_id
return { dropped_chunks: N, deleted_sessions: M }
```

**Invariants:**

- Table name `'anon_generation_log'` is a HARDCODED literal — no env
  var, no interpolation (T-9.1-10-04 mitigation).
- 30d retention via TimescaleDB drop_chunks (Pitfall #4: 1-day chunks
  give 30 efficient O(1) drops vs. 4 coarse 7d chunks).
- 7d unclaimed cleanup: claimed sessions stay indefinitely (project link).
- No try/catch around SQL — Inngest default retry policy applies on
  transient DB errors.

### Cron #3 — `anon-salt-rotate-v1` (daily 00:00 UTC)

Stable ID: `INNGEST_FUNCTION_IDS.ANON_SALT_ROTATE`. Schedule: `0 0 * * *`.

```text
step.run('generate-salt'):
   bytes = new Uint8Array(32)
   crypto.getRandomValues(bytes)
   newSalt = hex(bytes)  // 64 lowercase chars
step.run('rotate-salts'):  // SINGLE step for atomicity (T-9.1-10-02)
   INSERT INTO app_secrets (key, value, rotates_at)
   VALUES ('daily_salt_previous',
           (SELECT value FROM app_secrets WHERE key = 'daily_salt_current'),
           NOW() + INTERVAL '24 hours')
   ON CONFLICT (key) DO UPDATE SET value = EXCLUDED.value, rotates_at = EXCLUDED.rotates_at
   ;
   INSERT INTO app_secrets (key, value, rotates_at)
   VALUES ('daily_salt_current', ${newSalt}, NOW() + INTERVAL '24 hours')
   ON CONFLICT (key) DO UPDATE SET value = EXCLUDED.value, rotates_at = EXCLUDED.rotates_at
return { rotated: true, salt_prefix: newSalt.slice(0, 8) }
```

**Invariants:**

- Generate-salt SEPARATE step so Inngest memoizes `newSalt` — a retry
  of rotate-salts uses the same salt (otherwise it would orphan the
  just-promoted `daily_salt_previous`).
- Rotate-salts is a SINGLE step.run for atomicity — partial failure
  leaves the step un-memoized, full retry from scratch.
- Return shape exposes ONLY `salt_prefix` (first 8 hex chars) —
  T-9.1-10-03: Inngest dashboard surfaces step output, full salt MUST
  NOT leak.
- 24h grace window (`rotates_at = NOW() + INTERVAL '24 hours'`) pairs
  with `hashIpsForLookup()` dual-salt lookup so requests crossing
  midnight UTC don't lose rate-limit identity.

## Cost-runaway worst-case calculation

Cleanup cron silently fails for 24h:

| Input | Value | Notes |
|-------|-------|-------|
| Anon generations / hour | ~166 | Worst case: 1 anon per 15 min × 4 windows × 24h ≈ 4K orphan scripts |
| CF Workers cost / script-day | $0.02 | Estimate based on per-script-month metering |
| **Daily cost (24h silent failure)** | **~$80** | 4000 × $0.02 × 1 day |
| 3-day silent failure | ~$240 | + compounding new anons |

**Mitigation:** BetterStack heartbeat fires alert within 30 min of first
missed ping. Total exposure capped at ~30 min × 11 new anons ≈ $0.22.
Heartbeat is the difference between $0.22 and $240 in operator-blind
mode.

## Idempotency invariants per cron

| Cron | Idempotency mechanism | Re-run within same window |
|------|----------------------|---------------------------|
| `anon-tenant-cleanup-v1` | CF DELETE 404=success + per-row Inngest step memoization | Re-run picks up nothing new (rows already deleted); converges on { deleted: 0 } |
| `anon-rate-limit-cleanup-v1` | drop_chunks no-op when no chunks ≥ 30d; DELETE has no rows to remove | Re-run returns { dropped_chunks: 0, deleted_sessions: 0 } |
| `anon-salt-rotate-v1` | ON CONFLICT (key) DO UPDATE UPSERT + memoized `newSalt` | Re-run within same UTC day overwrites both rows but with the SAME `newSalt` (Inngest memoization); 24h grace timer resets |
