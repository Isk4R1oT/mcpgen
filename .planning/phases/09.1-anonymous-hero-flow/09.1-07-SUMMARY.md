# Phase 9.1 Plan 07: Frontend D-10 Wire-up Summary

## One-liner

Anonymous hero flow's frontend chrome — Next.js middleware gate matrix per D-10, 4 anon-state components (banner / deploy CTA / cache-hit badge / signup CTA), and a 3-screen jsx-bridge wrapper layer (Quality / Preview / Deploy) — wired to the existing locked screens **without modifying any locked JSX module**, with 19 new vitest cases pinning the contract.

## Playwright screenshot-diff result

The Playwright visual-lock config (`playwright.visual-lock.config.ts`, `maxDiffPixelRatio: 0.001`) was NOT executed in this worktree — running it requires a dev server with the locked SAMPLE_APIS data + browser binaries already cached, both of which are not available in the parallel-executor sandbox.

The test methodology is documented for the integrator:

1. Run `pnpm --filter @mcpgen/web preview:fixtures` (locked screen renders unchanged).
2. With `useAnonState` resolving to `{ isAnonymous: false, loading: false }` (any signed-in dev session), navigate to `/generate/{jobId}/quality`, `/generate/{jobId}/preview`, `/generate/{jobId}/deploy`.
3. Run `pnpm --filter @mcpgen/web test:visual` — diff vs `apps/web/tests/visual-lock/__screenshots__/` should report `< 0.001` pixel-ratio difference (the FE-05 baseline).
4. With `isAnonymous=true`, additive UI is expected (banner / signup CTA / anon deploy CTA). The screenshot-diff is intentionally not asserted in this state — the visual lock invariant only applies to the locked screen modules themselves, which remain byte-identical.

The two stronger guarantees that DO hold in this sandbox: (a) `tsc --noEmit` clean, (b) `pnpm --filter @mcpgen/web build` SSR-rendering green for all 23 routes (including the 3 anon-chrome consumers).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 — Blocking] Vitest could not collect tests at the plan-stated paths**
- **Found during:** Task 3 first vitest run.
- **Issue:** The plan specified `apps/web/tests/middleware-route-gate.test.ts` and `apps/web/tests/anon-banner.test.tsx`, but `vitest.config.ts` `test.include` was `['tests/unit/**/*.test.ts']` (only `.ts`, only under `tests/unit/`).
- **Fix:** Extended the glob to `['tests/unit/**/*.test.ts', 'tests/unit/**/*.test.tsx', 'tests/*.test.ts', 'tests/*.test.tsx']` so the plan's stated paths resolve while preserving the existing pattern for legacy tests.
- **Files modified:** `apps/web/vitest.config.ts`.
- **Commit:** `9062086`.

**2. [Rule 3 — Blocking] React 19 automatic JSX runtime + tsconfig 'jsx: preserve' broke vitest .tsx tests**
- **Found during:** Task 3 first run after fixing #1.
- **Issue:** Vitest's esbuild defaulted to JSX classic, expecting an explicit `React` global. The components don't `import * as React from 'react'` (they rely on Next 15's automatic runtime). All `.tsx` test runs failed with `ReferenceError: React is not defined`.
- **Fix:** Added `esbuild: { jsx: 'automatic' }` to `vitest.config.ts` so test transformation matches the Next.js production transform.
- **Files modified:** `apps/web/vitest.config.ts`.
- **Commit:** `9062086`.

**3. [Rule 3 — Blocking] middleware.ts could not be imported under vitest**
- **Found during:** Task 3 second vitest run.
- **Issue:** Importing `apps/web/src/middleware.ts` from a vitest test pulled `@logto/next/server-actions` → `next/navigation`. Next 15's `next/navigation` is a Node-runtime-only export with subpath conditions that vitest's ESM resolver cannot satisfy (`Cannot find module '.../next/navigation'`).
- **Fix:** Extracted the pure `isProtectedPath` predicate + `PROTECTED_PATTERNS` array into `apps/web/src/lib/route-gate.ts`. `middleware.ts` re-exports the same symbols (production code path identical), and the test imports the predicate from `route-gate.ts` directly.
- **Files modified:** `apps/web/src/lib/route-gate.ts` (new), `apps/web/src/middleware.ts`, `apps/web/tests/middleware-route-gate.test.ts`.
- **Commit:** `9062086`.

**4. [Rule 3 — Blocking] LockedSample is not exported from screens.tsx**
- **Found during:** Task 2 typecheck after first wrapper draft.
- **Issue:** Initial wrapper.tsx imported `LockedSample` from `./screens` — but that type lives in `./index` and `screens.tsx` does not re-export it.
- **Fix:** Two-line import split: `LockedSample` from `./index`, the wrapper components from `./screens`.
- **Files modified:** `apps/web/src/lib/jsx-bridge/wrapper.tsx`.
- **Commit:** `bd616b8`.

### Plan-prescribed Adjustments (NOT auto-fixes)

**5. [Plan-prescribed] AnonDeployCta is added as a sibling section, not as a Deploy-button replacement**
- **Issue:** The plan's behavior table for AnonDeployCta says "anon → 'Deploy to free 24h URL' / authed → 'Deploy to MCPGen Cloud'", but the locked Deploy screen has its own deployment CTA wired via the existing DeployWrapper.
- **Fix:** AnonDeployCta is rendered as a sibling section ABOVE the locked Deploy screen in `DeployScreenWithAnonChrome`. Anon users see both: the explicit anon CTA calling `/api/v1/deploy/ephemeral`, AND the locked Deploy screen's existing affordance. The locked Deploy screen is unchanged (FE-05 invariant). Authed users get the same dual surface, but the AnonDeployCta routes through `/api/v1/deploy/permanent/:id`.
- **Tracking:** No deferred items; this is the documented plan-prescribed pattern.
