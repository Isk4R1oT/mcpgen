       ```markdown
       # Drizzle Migration Conflict Resolution (T-1-04)

       **Decision drivers:** D-12 + RESEARCH §Pitfall #18 + docs/decisions/001-drizzle-timestamp-prefix-native-format.md.

       ## Prevention (default — should never need this runbook)
       - All migrations use `prefix: 'timestamp'` (drizzle-kit native) producing `YYYYMMDDHHMMSS_<name>.sql`.
       - Pre-commit hook `ir-codegen-check` (Plan 02) catches IR drift; not migrations directly — that's CI.
       - CI `ops` job runs `pnpm --filter @mcpgen/contracts drizzle-kit:check` on every PR; collisions fail the check.

       ## When two PRs introduce migrations within the same second
       Theoretical race: parallel worktrees both generate migrations in the same second.

       ### Resolution procedure
       1. The PR that merges second sees `drizzle-kit check` fail with "duplicate timestamp prefix".
       2. Author re-runs `pnpm --filter @mcpgen/contracts drizzle-kit:generate` against the post-merge `main` to produce a new file with a current timestamp.
       3. Hand-merge the SQL DDL from the failed file into the new file (rare; usually a single CREATE TABLE block).
       4. Delete the old colliding file; commit; re-PR.

       ### Why we don't auto-rename
       Drizzle-kit emits one file per generate run; auto-renaming would silently lose the file's content if the rename collides. Surfacing the conflict at PR time is the safer trade.

       ## Sub-second collision
       Has not been observed in practice. If it occurs:
       - Add a manual suffix `_a` / `_b` to one filename (e.g., `20260427000000_a_init_schema.sql`).
       - Document the suffix in `docs/decisions/<date>-migration-suffix.md` for traceability.
       ```
