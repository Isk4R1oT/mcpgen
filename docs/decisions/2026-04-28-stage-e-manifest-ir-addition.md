# 2026-04-28 — Stage E Manifest + QualityReport bumps + Pass5Output.flags (IR additive change)

## Status

Accepted.

## Context

Phase 4 (Generation Engine — Pass 5 + Stage E codegen) requires four
strictly-additive extensions to `packages/ir/src/types.ts` (Zod source of
truth → CI-regenerated `packages/ir/python/types.py`) before Stage E
implementation lands.

The extensions close two gaps identified during research:

1. **RESEARCH Open Question 1** — `StageEManifest` Zod type missing.
   `04-CONTEXT.md` D-34 (L1 cache value) and D-43 (`<fixture>/stage-e-output/MANIFEST.json`
   acceptance reference) both reference `StageEManifest`, but Phase 1 D-02 IR
   freeze missed the type. Without it the L1 cache value and fixture
   manifest are validated by hand-typed JSON parsing instead of Zod, leaving
   the contract untyped at the most consequential boundary (cache hit-rate
   determinism per GEN-12).

2. **CONTEXT D-42** — `QualityReport` needs `bundle_size_kb` (filled by
   Stage E `validate.py` Plan 04-11 from `wrangler deploy --dry-run`) and
   `pipeline_versions` (per-pass version stamps consumed by the Phase 8
   Drift Watcher).

3. **CONTEXT D-12** — `Pass5Output` needs an additive `flags` bag so Pass 5
   can surface per-server diagnostics (`server_pagination_strategy`,
   `prompt_injection_warnings_count`) consumed by the SSE pipeline event
   `partial_result.pagination_strategy` (per Code Example 9).

4. **WARNING #5** — Reviewer flagged that `StageEManifest.ts_compile_passed`
   has ambiguous semantics. Distinguishing "no compile errors" from "no
   compile errors AND no warnings" matters for the per-fixture acceptance
   gates (D-43.5 zero-warning gate applies only to Stripe + GitHub +
   Notion, not Linear or Slack). Adding `ts_compile_warning_count: int >= 0`
   resolves the ambiguity.

## Decision

Extend `packages/ir/src/types.ts` strictly-additively:

```typescript
// NEW types (Phase 4 only consumer pre-Phase-4-merge):
export const StageEFileEntry = z.object({
  relative_path: z.string(),
  sha256_content_hash: z.string().regex(/^[a-f0-9]{64}$/),
  render_template: z.string(),
  render_inputs_hash: z.string().regex(/^[a-f0-9]{64}$/),
});

export const StageEManifest = z.object({
  files: z.array(StageEFileEntry),
  bundle_size_kb: z.number().nonnegative(),
  ts_compile_passed: z.boolean(),  // semantics: "no `tsc --noEmit` ERRORS"
  ts_compile_warning_count: z.number().int().nonnegative().default(0),
  template_version: z.string(),
  generated_at: z.string().datetime(),
});

// EXISTING types (additive bumps):
export const Pass5Output = z.object({
  tools: z.array(FinalTool),
  flags: z.record(z.string(), z.unknown()).optional(),  // NEW
});

export const QualityReport = z.object({
  // ... existing fields ...
  bundle_size_kb: z.number().int().nonnegative().nullable().optional(),  // NEW
  pipeline_versions: z.record(z.string(), z.string()).nullable().optional(),  // NEW
});
```

Regenerate `packages/ir/python/types.py` via `pnpm --filter @mcpgen/ir codegen`
and commit the regenerated bytes (Phase 1 D-02 deterministic-codegen contract).

## Authoritative semantics for `ts_compile_passed` / `ts_compile_warning_count`

- `ts_compile_passed = true` ⇔ `tsc --noEmit` exits 0 with NO errors. Warnings
  are allowed and tracked separately in `ts_compile_warning_count`.
- For acceptance fixtures Stripe + GitHub + Notion (CONTEXT D-43.5 zero-warning
  gate): both `passed=true` AND `warning_count=0` are required.
- For acceptance fixtures Linear + Slack: only `passed=true` is required;
  `warning_count` may be non-zero (surfaced via Sentry/observability for
  cleanup follow-ups, never blocking the pipeline).

## Consequences

### Pre-Phase-4 consumers — UNAFFECTED

- All four schema extensions are strictly-additive (`flags`, `bundle_size_kb`,
  `pipeline_versions` are `.optional()`/`.nullable().optional()`; the new
  `StageEManifest` and `StageEFileEntry` types have no existing consumers).
- Phase 1 fixture replays (`pass-0-output.json`, `pass-1-output.json`,
  `pass-2-output.json`, `pass-3-output.json`, `pass-4-output.json`,
  `quality-report.json`) continue to validate without modification.
- `pnpm --filter @mcpgen/ir test` (34 unit tests) passes after regen.

### Phase 4 consumers (all introduced by this plan + downstream Phase 4 plans)

- Plan 04-06 (Stage E scaffold, this plan) — emits an initial `StageEManifest`
  from `output_writer.py` with placeholder `bundle_size_kb=0` and
  `ts_compile_passed=False` (filled by `validate.py` in Plan 04-11).
- Plan 04-11 (Stage E validate) — fills `StageEManifest.bundle_size_kb` from
  `wrangler deploy --dry-run` parse + `ts_compile_passed` /
  `ts_compile_warning_count` from `tsc --noEmit` exit code + stderr parse.
- Plan 04-12 (Stage E fixture acceptance) — `<fixture>/stage-e-output/MANIFEST.json`
  uses the `StageEManifest` shape; per-fixture gates apply per the
  authoritative semantics above.

### Post-Phase-4 consumers

- Phase 5 (Stage F) — `QualityReport.bundle_size_kb` consumed by F1 static
  bundle-size gate (≥ 950 KiB → hard fail). `QualityReport.pipeline_versions`
  surfaced in the public quality badge.
- Phase 8 Drift Watcher — `QualityReport.pipeline_versions` compared
  against the latest engine version per-pass; Drift Watcher triggers
  regeneration when any pass version bumps AND the spec_hash is unchanged
  (handles "MCPGen pipeline improved, regenerate to harvest").

## Codegen pipeline

`packages/ir/scripts/codegen.ts` (Phase 1 D-02) runs unchanged:

1. Author Zod in `src/types.ts` (this commit).
2. Convert each top-level Zod export to JSON Schema (Zod 4 `z.toJSONSchema`).
3. Run `datamodel-code-generator==0.26.4` to produce `packages/ir/python/types.py`.
4. CI runs `pnpm --filter @mcpgen/ir codegen:check` on every PR touching
   `packages/ir/`.

After this commit `pnpm --filter @mcpgen/ir codegen:check` succeeds.

## Alternatives considered

- **Defer `StageEManifest` to Plan 04-11.** Rejected: Plan 04-06 needs the
  type to write `output_writer.py`'s return value with strict typing.
  Deferring means hand-typed dicts in two intermediate plans before the
  type catches up — the kind of typing-debt CLAUDE.md global rule
  "no generic `Dict[str, Any]`" forbids.
- **Hand-roll `StageEManifest` only on the Python side** without bumping
  the Zod source. Rejected: violates Phase 1 D-02 invariant
  (`packages/ir/src/types.ts` is the single source of truth; Python is
  generated). The tooling diff would surface in `codegen:check` CI.
- **Make `bundle_size_kb` non-nullable.** Rejected: Phase 4 fills it, but
  Phase 1/2/3 fixtures already shipped with `quality-report.json` lacking
  the field; non-nullable would break those replays.

## Migration

None required. All consumers post-this-commit see the new fields; pre-this-commit
artifacts continue to validate because every new field is optional/nullable.
